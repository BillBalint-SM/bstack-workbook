# QA report

Target, date, source revision/content identity, mode, allowed actions and scope.
List actual pages/flows tested, viewports and unavailable prerequisites.

## Findings
For each observed defect: ID, severity/category, target location, exact steps,
expected versus actual behavior, evidence link and verification limits.
No issue quota; no finding is also a result when its tested scope is explicit.

## Checks
State pass/fail/blocked/not-run by named behavior. Optional scores must identify
their rubric and tested coverage. Use comparable baselines only.

## Changes (qa or authorized design fixes only)
List issue → changed files → actual retest result. Separate verified, unverified
and deferred fixes. Include before/after evidence and meaningful regression
checks. Do not claim a commit or deployment that did not occur.

## Remaining scope
Unresolved defects/decisions, blocked and untested paths. A narrow QA pass does
not by itself establish release readiness.
