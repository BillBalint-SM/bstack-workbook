# Developer experience review dimensions

- Entry: prerequisites, installation scope, first command and observable result;
  minimize steps while preserving explicit credentials and safety boundaries.
- Interface: naming, defaults, consistency, discoverability, useful error codes,
  retries/idempotency and offline behavior when relevant.
- Debugging: what failed, why, safe correction and diagnostics without secrets.
- Documentation: complete examples, expected output, navigation and version fit.
- Migration: compatibility, reversible data changes and honest deprecations.
- Tooling: local setup, testing, CI and editor integration only as applicable.
- Support: actual routes for help and ecosystem fit, no invented community data.
- Measurement: planned persona/journey, friction and a measurable first success.

For Codex skills specifically check name/description, discoverability, real
tools, scoped side effects, question boundaries, output validation and useful
missing-prerequisite messages. No other-host setup or automatic installation.

A deep review may include an empathy narrative, competitive comparison,
scorecard and prioritized implementation checklist. To compare plan with reality,
execute devex-review later only when requested; pass the target and inspect
its actual measurements.
