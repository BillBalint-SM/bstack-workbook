# Office hours

Read [HOST.md](../../HOST.md). This workflow produces a design brief, not
implementation code. Use the shared lifecycle when saving a result; a no-file
conversation does not need state writes.

1. Read the user's existing brief and relevant local project files/designs.
   Use [bontaflow-memory](../bontaflow-memory/SKILL.md) for a requested local
   decision/learning lookup. Execute that lookup and consume its actual result;
   absent records are not evidence of a prior preference.
2. Choose the mode from the stated goal: a business/customer problem uses
   [startup diagnosis](sections/phase-2a-startup-diagnostic.md); learning, a
   personal tool or creative exploration uses
   [builder brainstorming](sections/phase-2b-builder-brainstorm.md). Clarify only
   if the goal is genuinely ambiguous. Do not impose revenue metrics on a hobby.
3. Establish the concrete user, current workaround, desired outcome and
   constraints. Ask only unanswered material questions. Existing answers count;
   respect a request to skip optional questions and label remaining assumptions.
4. Challenge the consequential premises: why act, why this problem, what can
   existing code/tools do, and how will the result reach its user? Distinguish
   observed demand from interest and assumptions. Never invent market evidence.
5. Compare two genuinely different approaches when there is a real choice;
   include the smallest useful version. Give effort, risk, reuse and tradeoffs.
   A small settled request need not manufacture alternatives. Recommend one;
   reuse a prior choice or leave an unresolved consequential decision open.
6. Create the bounded design brief using
   [design and handoff](sections/design-and-handoff.md). Check it once against
   the stated goal, chosen approach and constraints. Do not claim agreement
   from silence or mark an unchosen approach as approved.
7. Return the checked design and one concrete next action. If an ensuing skill
   was requested, execute the relevant `spec`, `plan-ceo-review`,
   `plan-eng-review` or design skill under HOST's handoff contract and consume
   its result. A recommendation alone is not execution.

Landscape research, independent opinions, visual sketches, image alternatives
and deeper review are available when the request or a specific uncertainty
warrants them. Use available Codex tools, the packaged `browse` skill, or an
available user-selected diagram/image skill; do not install or launch another
host. Clearly label unavailable work. Personal profiles, recurring mentoring
routines, external memory, unsolicited publishing and automatic implementation
are outside the default flow. Record a learning only through `bontaflow-memory`
and only within the task's authorization.
