# Developer experience reference

Use these lenses when relevant; examples are patterns, not mandatory features
or claims about a particular vendor.

1. Getting started: a clear prerequisite and the shortest runnable first result.
2. API/CLI/SDK: consistent names, discoverable help and explicit error status.
3. Errors: what failed, likely cause, concrete recovery and relevant context.
4. Documentation: working examples, accurate references and useful navigation.
5. Migration: compatibility limits, deprecation notice and tested recovery.
6. Environment: reproducible commands, checks and supported platforms.
7. Support: a findable way to report a problem without exposing private data.
8. Measurement: observed step count, command duration and completion conditions.

For Codex skills, keep discovery metadata precise, common rules in HOST,
package-relative dependencies and real same-task handoff evidence. Missing
authentication, trust or a tool must remain visible. No fixed score or presumed
adoption percentage replaces actual observations.
